# ADR-001: Knowledge와 Runtime Config 두 파일 분리, Knowledge 읽기 전용
대상: `<SAD-R001>`
상태: 채택

## 맥락
분류 기준 데이터와 운영 설정을 어디에 어떻게 둘지 정한다.

The PRD (section 2, `<PRD-U005>`) and SRS revision `00.01` (`<SRS-F001>`, `<SRS-F002>`, `<SRS-F005>`, `<SRS-F006>`, §8.2, §8.3) separate a human-maintained Knowledge Layer from a UI-editable Runtime Config Layer. The SAD records this as an architecture decision because both files are user-facing contracts placed in each project folder.

## 결정
분류 지식은 `문서목록.json`, 운영 설정은 `ledger.config.yaml`에만 두고 시스템은 Knowledge에 쓰지 않는다.

`문서목록.json` holds Phases, abbreviations and full names and is read-only to the CLI and the UI. `ledger.config.yaml` holds paths, thresholds and policies and is written only by the validated UI save path. Neither is cached in a database, a cache file or code constants.

## 고려한 대안
단일 설정 파일과 UI 편집 가능한 Knowledge를 검토했다.

- One combined YAML file holding both Knowledge and settings.
- Knowledge editable from the settings UI.

## 선택 근거
사용자 소유 데이터 보호와 코드 수정 없는 확장을 우선했다.

Separation lets the UI save settings without any path that could corrupt Knowledge, lets the Knowledge owner edit the list with no sync step, and lets a new Phase work through file edits alone (`<SRS-N002>`, `<SRS-N006>`). A combined file or UI-editable Knowledge would give the system a write path to user-owned reference data.

## 되돌리는 비용
두 파일 계약·UI 범위·불변성 시험을 함께 바꿔야 한다.

Reversal changes both file schemas used in every project folder, requires migrating existing files, widens the UI to Knowledge editing and invalidates the Knowledge hash/mtime regression test. Cost: 높음.
