# ADR-002: 상주 없는 온디맨드 1회 실행 프로세스
대상: `<SAD-R002>`
상태: 채택

## 맥락
분류 실행을 상주 감시로 할지 1회 실행으로 할지 정한다.

SRS revision `00.01` §5.2 states an on-demand CLI run plus a local GUI with no resident process, and §9 excludes daemon, polling and scheduler registration code. The code built before that SRS (`src/app/adapters/file_watcher.py`, `src/app/main.py`) runs a resident watchdog/polling watcher controlled from the GUI.

## 결정
`idma run`은 검증·1회 탐색·처리 후 종료 코드로 끝나고, `idma ui`는 별도 설정 프로세스다.

`idma run` validates, scans `source_root` once, processes every target sequentially and exits with code 0, 1, 2 or 3. `idma ui` is a separate local GUI process for settings. There is no daemon, polling loop, scheduler registration or tray residency.

## 고려한 대안
현행 코드의 상주 감시 방식을 검토했다.

- Resident watcher (watchdog events with polling fallback and file stabilization), started and stopped from the GUI, as in the current code.

## 선택 근거
SRS 제약과 단일 검증 지점·종료 코드 계약을 따른다.

A one-shot run gives one validation point before any move, a defined exit-code contract (SRS §8.1), one `run_id` per run for log records, and one workbook open per run for lock detection. The resident alternative is outside the SRS and needs stabilization and concurrency rules the SRS does not define.

## 되돌리는 비용
종료 코드·로그 실행 단위·워크북 잠금 처리·운영 절차가 바뀐다.

Moving to a resident model changes the exit-code contract, the run/file log record model, workbook lock handling, the UI scope and the user's operating procedure, and requires new requirements for stabilization and concurrency. Cost: 높음.
