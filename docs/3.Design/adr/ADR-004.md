# ADR-004: Rule 우선, AI는 단일 추상 계약 뒤의 보조 분류
대상: `<SAD-R004>`
상태: 채택

## 맥락
분류에서 Rule Engine과 AI의 역할과 결합 방식을 정한다.

The PRD (`<PRD-N003>`, `<PRD-A001>`, `<PRD-A003>`) and SRS revision `00.01` (`<SRS-F014>`, `<SRS-F015>`, `<SRS-F017>`, `<SRS-N003>`, §8.6) require Rule-first classification, AI only for listed conditions, a single implementation-independent AI interface, and operation without any AI implementation.

## 결정
결정론적 Rule Engine이 먼저 판정하고 AI는 3개 조건에서만 단일 `classify` 계약으로 호출한다.

AI is reached only through `classify(filename, artifacts) -> AIResult | None`. The caller never depends on whether the implementation is local or remote. Any AI exception, `None` or response slower than 30 s degrades to Fallback for that file only.

## 고려한 대안
AI 우선 분류와 공급자 API 직접 호출을 검토했다.

- AI-first classification with Rule as a hint.
- Calling a vendor SDK directly from the classification code.

## 선택 근거
재현성·감사 가능성·AI 없는 운영을 보장한다.

Rule-first keeps results deterministic and explainable in `match_evidence`, keeps AI calls at zero for files Rule can decide, and keeps the system usable when no AI is available. The single contract keeps vendor choice out of core logic.

## 되돌리는 비용
관리대장·로그 기록의 의미와 결정론 시험, 핵심 로직의 공급자 결합이 바뀐다.

Making AI primary or exposing a vendor API changes the meaning of `classification_method` and `match_evidence` in every existing ledger row and log record, breaks the determinism and zero-AI-call regression tests, and couples core logic to one vendor. Cost: 높음.
