# ADR-005: 사용자가 실행해 둔 동안 source_root를 상주 감시하는 단일 프로세스
대상: `<SAD-R005>`
상태: 채택

## 맥락
1회 실행 결정(ADR-002)과 실제 운영 방식이 달라 사용자가 운영 방식을 정했다.

ADR-002 recorded a one-shot `idma run` process because SRS revision `00.01` excluded resident processes. The code (`src/app/main.py`, `src/app/adapters/file_watcher.py`, `src/app/ui/settings_window.py`) runs a resident watcher started from the GUI or at `--nogui` start, with a dashboard and tray. On 2026-10-10 the user answered DISC-007 Q02 with "Q2 기능을 문서에 명시": document these existing features. PRD `00.03` (`<PRD-F020>`, `<PRD-F021>`) and SRS `00.05` (`<SRS-F009>`, `<SRS-F044>`–`<SRS-F046>`) now state them.

## 결정
한 번 실행한 프로세스가 감시 세션 동안 안정화된 파일을 1건씩 처리한다.

One process per user launch, GUI mode by default or `--nogui`. It validates once at startup. During a watch session it detects direct files of `source_root` through watchdog events, or by polling every `watch.scan_interval_seconds` when watchdog is unavailable, waits until each file is stable for `watch.file_stable_seconds`, and processes files one at a time. There is no one-shot run command, OS service or scheduler registration.

## 고려한 대안
기존 1회 실행 방식과 두 방식 병행을 검토했다.

- Keep the one-shot `idma run` (ADR-002) and remove the watcher, dashboard and tray from the code.
- Offer both a one-shot command and the resident watcher.

## 선택 근거
사용자 결정과 현행 코드가 쓰는 운영 방식을 따른다.

The user chose to document the existing behavior. The current code has no one-shot command, so keeping one as an option would add an unimplemented feature. The resident model processes dropped files without re-running and lets the GUI show progress.

## 되돌리는 비용
명령행·종료 코드·세션 모델·백업 시점·GUI 기능과 운영 절차가 함께 바뀐다.

Returning to a one-shot run changes the CLI and exit-code contract, the session and `run_id` model, ledger backup and lock timing, the dashboard and tray, and the user's operating procedure. Cost: 높음.
