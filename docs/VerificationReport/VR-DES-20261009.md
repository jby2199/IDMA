## 1. 검토 범위

Design V&V 3개 Task(추적성 분석, 소프트웨어 설계 평가, 인터페이스 분석)를 SAD 전체와 ADR 4건에 적용했다. SAD-only 정책(§4.7)에 따라 SDD 상세는 검증하지 않았고, `docs/3.Design/SDD.md`에는 `명시 결정` 블록이 없음을 확인했다(`grep` 0건). 코드는 SAD `현행 코드 대응` 표의 사실 여부 확인에만 사용했으며 구현 V&V는 수행하지 않았다.

적용 렌즈(Review mode): Completeness/Traceability, Correctness/Accuracy, Consistency/Interfaces, Readability/Unambiguity, Testability/Evidence.

제외: 구현 V&V, 시험 설계·실행, PRD/SRS 자체의 요구사항 V&V(상위 결함은 설계 판정에 영향을 주는 범위에서만 기록), 위험·보안 분석.

## 4. 발견사항

근거: `SAD.md:191`, `SAD.md:193`, `SAD.md:466`, `SAD.md:577`, `SAD.md:287`
영향: 원자 저장 소유 컴포넌트가 문서상 둘로 갈려 구현·시험 배정 혼선.

### D-04 관리대장 행 기록 실패 시 상태·파일 위치 미결

문제: `SAD-C005` 순서는 분류 → 배치 → 대장 → 로그이고 `SAD-I005`는 "per-row write failure marks that file `Error`"라 한다. 이 경우 파일은 이미 이동된 뒤라 `<SRS-F025>`("`Error` 파일은 이동하지 않고 `source_root` 보존")와 충돌하고, 기록 실패 행은 `<SRS-N005>`(행 수 = 대상 수)를 만족할 수 없다. `<SAD-Q007>`이 워크북을 1회 열기로 하면 저장 시점 실패가 이미 이동된 전체 파일에 영향.
근거: `SAD.md:219-220`, `SAD.md:315`, `SAD.md:391`, `SRS.md:364-367`, `SRS.md:357-360`, `SRS.md:517-518`

필요한 수정 또는 확인: SRS가 `<SRS-F025>`의 "관리대장 행 기록 실패"와 "이동하지 않음"의 순서 관계를 확정한 뒤 SAD가 기록·저장 시점을 결정. 소유 단계: docs(SRS 우선, 이어서 SAD).

### D-06 `[SAD-X001]` 근거 SRS 문구 모호

근거: `SAD.md:486-490`, `SRS.md:192-193`, `SRS.md:467-469`
영향: UI 통과·실행 차단 차이의 실제 범위가 SRS 해석에 좌우.
필요한 수정 또는 확인: SRS가 (4)의 대상(디렉토리 자체 vs 상위)을 확정. SAD는 헤더 검사 차이 추가. 소유 단계: docs(SRS 우선).
