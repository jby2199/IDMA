## 5. 발견사항

### D-15r `<SAD-C001>` 책임 목록에 헤더 누락 종료 코드 배정 누락

문제: `<SAD-C001>`은 종료 코드 매핑을 맡고(`SAD.md:196` "maps outcomes to exit codes"), `<SAD-C003>`은 종료 코드 결정을 비책임으로 둔다. 그런데 `<SAD-C001>` 책임 목록(`SAD.md:197`)에는 종료 코드 1이 "`<SAD-C003>`이 startup failure를 보고할 때, 창이나 세션 이전"으로만 배정돼 있다. 세션 시작 시 헤더 누락에 대한 무GUI 종료 코드 1과 GUI `Stopped`·원인 표시가 빠졌다. 같은 목록은 잠김(종료 코드 2)에 대해서는 모드별 동작을 적는다. D-15 정정이 `<SAD-I001>`·`<SAD-I005>`에만 반영되고 소유 컴포넌트까지 전파되지 않았다.
근거: `SAD.md:196-197`, `SAD.md:215-216`, `SAD.md:154`, `SAD.md:301`, `SAD.md:337`, `SRS.md:472-475`
영향: 구현자가 컴포넌트 책임만 보고 작업하면 헤더 누락이 "startup failure" 경로(창 미기동)로 처리될 수 있다. 이것은 D-15에서 해소하려던 바로 그 혼동이다. `SAD.md:197`의 "enforcing the startup and session start order above"가 `SAD.md:154`를 간접 참조하므로 차단성은 아니다.
필요한 수정 또는 확인: `<SAD-C001>` 책임에 "세션 시작 시 `<SAD-C003>`이 헤더 누락을 보고하면 무GUI 종료 코드 1, GUI는 원인 표시 후 `Stopped`"에 해당하는 배정을 추가할 것. 소유 단계: docs(SAD).
결과: FAIL (경미)

### D-16 SRS §8.2.1에 `ledger.config.yaml` 보존 규칙이 들어가 "다른 키 무시"와 충돌

문제: §8.2.1 `app.config.yaml` 절의 마지막 항목(`SRS.md:710`)이 "위 8개 필수 항목 외의 키는 무시하지 않고 그대로 보존해 저장한다(`<SRS-F043>`)"이다. 이 규칙은 `ledger.config.yaml`(§8.2, 8개 필수 키)의 저장 규칙이다. 그러나 같은 절 `SRS.md:707`은 "이 파일의 다른 키는 무시한다"고 하고, `app.config.yaml`은 시스템이 쓰지 않는 파일이다(`SAD.md:308`). `git blame` 결과 이 줄은 `48d4b14`의 §8.2 항목이고, `ae666ac`에서 §8.2.1 제목이 그 앞에 삽입되면서 위치가 바뀌었다. 직전 검토(§9)에서는 놓쳤다.
근거: `SRS.md:699`, `SRS.md:707`, `SRS.md:710`, `SRS.md:664-697`, `SAD.md:308`, `SAD.md:310`
영향: 절 구조대로 읽으면 `app.config.yaml`에 대해 "무시"와 "보존해 저장"이 함께 요구된다. SAD는 두 파일을 올바르게 구분하므로(`<SAD-C002>` `SAD.md:206`, `<SAD-I002>` `SAD.md:308`) 설계 판정에는 영향이 없다. 다만 SRS 단독 독자와 시험 작성자는 오해할 수 있다.
필요한 수정 또는 확인: 해당 항목을 §8.2 끝(`SRS.md:697` 다음)으로 옮길 것. 소유 단계: docs(SRS).
결과: FAIL (경미)

### D-17 설정 파일이 둘이 되면서 "설정 파일 없음 → stderr만" 문구가 모호해짐

문제: D-14 정정으로 `app.config.yaml` 부재도 기동을 차단하게 됐다. 이 경우는 `project_root`가 이미 확정된 상태이므로 원인을 stderr와 로그에 남긴다(`SRS.md:708-709`). 반면 stderr 전용 예외를 기술하는 문구는 여전히 대상 파일을 한정하지 않은 "설정 파일"로 쓴다. 특히 `<SAD-Q008>` 확인 방법(`SAD.md:431`)은 "for a missing config file ... checking stderr only"를 조건 없이 나열한다. 문자 그대로 읽으면 `app.config.yaml` 부재 시험의 기대값이 stderr 전용이 되어 §8.2.1과 충돌한다. `SRS.md:217`, `SRS.md:635`, `SAD.md:301`은 "`project_root`를 확정할 수 없는"으로 범위를 한정하므로 논리적으로는 맞지만, 괄호 안 예시 "설정 파일 없음"이 같은 모호성을 남긴다.
근거: `SAD.md:431`, `SAD.md:301`, `SRS.md:217-219`, `SRS.md:634-636`, `SRS.md:708-709`
영향: 종료 코드 1 시험(`<SAD-Q008>`)에서 `app.config.yaml` 부재 경로의 로그 기대값이 문서마다 다르게 읽힌다.
필요한 수정 또는 확인: `<SAD-Q008>` 확인 방법과 해당 괄호 예시를 `ledger.config.yaml`로 한정할 것. 예를 들어 "`ledger.config.yaml` 없음·파싱 실패·`project_root` 키 누락"처럼 쓸 수 있다. `app.config.yaml` 부재는 stderr와 로그 사례로 분리한다. 소유 단계: docs(SAD 우선, SRS 문구 정렬).
결과: FAIL (경미)
