# ZIP 문서 관리 규칙 도입 — IDMA
기존 요구를 유지하면서 문서 판과 작업 수락 근거를 연결한다. 현재 상태: 문서 관리 전환 완료. 제품 전체의 남은 확인사항은 아래 기록대로 유지.

## 범위와 근거
이번 작업은 기존 문서의 관리 기준 도입이며 제품 합의·시험을 새로 승인하지 않는다.

- 사용자 원문(2026-10-06): “`PFOA-프로젝트폴더정리기` 제외한 나머지에 반영 진행.”
- [반영 계획](../../../../../1.reference/ZIP-개발환경-실제문서반영계획서.md), [공통 근거 계약](../../../../../.claude/skills/by-orchestration/references/requirements-evidence.md), [워크스페이스 작업](../../../../../4.docs/notes/LLM작업/진행중/zip-document-rollout-2026-10-06.md).
- 제외: 제품 동작·요구 의미 변경, 누락 SAD 신규 작성, 과거 승인·수락 이력 조작. 원문 요구·ID·기존 개정 이력을 보존한다.
- `00.01`을 도입한 경우 현재 본문의 합의 기준을 확정하지 못한 관리 초판이다. 과거 요구의 효력 취소나 새로운 제품 승인으로 해석하지 않는다.

## 제약·사례·설계 영향 대조
기존 내용 보존과 미확인 제품 검증을 구분한다. 아래 항목은 작성자 대조를 바탕으로 하며 독립 판정은 후속 V&V 보고서를 따른다.

- PRD-A001~008의 Rule/AI/폴백·파일명·설정·CWD 조건 보존. PRD-A005 파일명 불변과 중복 suffix의 적용 경계는 기존 표현을 유지했으며 이번 도입이 의미적 해소를 뜻하지 않는다.
- 기존 SAD 파일 없음. 새 설계 작성은 별도 후속 작업이다.

- SRS-N007/부록 B 성능 목표는 본문상 PRD 근거 없는 설계 결정으로 표시되어 있다. 새 판 도입을 상위 합의로 해석하지 않는다.

## 기존 작업과 현재성
기존 기록은 보존하며 새 판 도입만으로 이전 구현·시험을 재수락하지 않는다.

- [초기빌드-잔여확인.md](<초기빌드-잔여확인.md>)

위 기존 기록의 입력 판·수락 origin과 현재 산출물 일치는 이번 전환으로 입증되지 않았다. 해당 기록을 다음 실행 시 확인하고, 근거가 없으면 `현재성 미확인`을 유지한다. 종료 기록의 과거 판정행을 고치지 않는다.

## 검증과 실패 복구
이번 관리 전환 수락과 제품 전체 단계 판정을 구분한다.

- 독립 검증: [VR-REQ-EVAL](../../../VerificationReport/zip-document-adoption/VR-REQ-EVAL.md). 이번 CHANGE_SET 범위 PASS; 전체 제품 승인·시험 현재성 재확인 제외.
- 작성 검사: 원래 HEAD 대비 동일 인자·동일 출력·동일 종료코드. 실제 결과·대상 해시는 [원시 검사 기록](../../../../../4.docs/notes/LLM작업/진행중/zip-document-rollout-2026-10-06/validation.json) 참조. PIET의 기존 작성 검사 FAIL은 그대로 보존.
- 단계 gate: `pwsh -NoProfile -File tools/gate.ps1 docs`, exit 1, **FAIL**. [실제 gate](../../../../tools/gates/docs.GATE.md) · [원시 실행 기록](../../../../../4.docs/notes/LLM작업/진행중/zip-document-rollout-2026-10-06/gates.json).
- 작업 수락: 문서 관리 전환 T01 **1/1**. 제품 요구 충족률·실사용 검증은 미평가. 커밋 전 수락행은 origin 식별 대기이며 커밋 뒤 추가 이력·부모·현재 경로를 대조한다.

### 단계 실패와 재개 조건
이번 관리 변경이 만들지 않은 단계 차단사항을 후속 범위로 유지한다.

- 실작업 SAD 문서 없음 — SAD 필수. SDD는 더 이상 검사하지 않음 (docs/3.Design/SAD.md 작성; *SAD*.md, 대문자만, (template) 제외)

- 원인 판정: 기존 문서 부재·내용 결함 또는 예시의 gate 제외. 이번 판 도입의 회귀와 분리한다.
- 다음 행동·재개 조건: 별도 제품 설계/요구 보완 작업에서 상위 근거를 확정하고 해당 원문을 보완한다. PROJ-template는 실제 프로젝트를 만들 때 예시를 실작업 문서로 구체화한다. 영향 범위 독립 V&V 후 같은 docs gate를 재실행한다. 이번 작업에서는 제품 의미를 바꾸거나 없는 SAD를 작성하지 않는다.
- 재검증 결과: 현재 FAIL. 후속 해결 미수행. 이 미완료 상태 때문에 도입·현재성 기록은 진행중 위치에 유지한다.
